# Platform files, mappings, and pipes

`SIRPlatformFile` owns a regular-file native handle and offers sequential and positional operations. `SIRPlatformFileMapping` borrows an open file **only while establishing** the view, then retains its own OS mapping lifetime; `SIRPlatformPipe` owns a pair of anonymous stream endpoints. All public types live in the global namespace and are independent of Resources/GRDG.

- `SIRPlatformFileMapping::map(file, offset, bytes, mode)` supports read-only, shared read-write, and private copy-on-write mappings. `bytes == 0` means map to EOF; mapping an empty file or an offset at/after EOF returns `SIR_FILE_OUT_OF_RANGE`. The OS allocation granularity is handled internally, with the requested range exposed via `getData()` and `getSize()`. `flush()` persists dirty shared pages through `msync(MS_SYNC)` or `FlushViewOfFile`; callers that require durable file metadata must also maintain their own `SIRPlatformFile::flush()` sequence. Shared writable mappings do not automatically extend the file. The caller must ensure the mapped file is not truncated or concurrently changed in incompatible ways while mapped; this avoids SIGBUS or invalid mapped access. Mapping bytes are OS-backed views, **not** allocations from GRDG's canonical CPU pool.
- `SIRPlatformPipe::create()` creates blocking, non-inheritable read and write ends. `read()` returns a partial byte count and `SIR_PIPE_END_OF_STREAM` once the writer has closed and the buffer is empty. `write()` loops for the full request, reports partial transfers on failure, and returns `SIR_PIPE_BROKEN` on a disconnected reader. On Linux, SIGPIPE is masked only on the writing thread during the native write and the generated signal is consumed on EPIPE, without changing process-wide signal handlers. Separate threads may operate the distinct ends, but a close on an endpoint must not race its own active operations. The API provides byte streams, not message framing, nonblocking I/O, or subprocess launch/redirect orchestration.

Native ownership: `Source/Core/Platform/Linux/` implements `mmap`, `munmap`, `msync`, and anonymous `pipe2`; `Source/Core/Platform/Windows/` implements file sections/views and `CreatePipe`. Tests live in `Tests/Unit/SIRPlatformFileMappingTests.cpp` and `SIRPlatformPipeTests.cpp`.
